# TA08.008 — Third-Party Tracker Exposure

## Overview

| Field | Value |
|-------|-------|
| **ID** | TA08.008 |
| **Tactic** | [Access Control Subversion](../../tactics/TA08-access-control.md) |
| **Severity** | High |
| **AISS Score** | 7.0 |
| **System Types** | A, B, C, D, E, F, G |

## Description

Third-party tracking services (session recording, analytics, advertising pixels, heatmaps) are embedded in web portals that serve or interact with AI systems — often without user consent, adequate disclosure, or security review. These services capture user behaviour data including mouse movements, click patterns, scroll depth, form inputs, and session replays, creating both a privacy compliance violation and an attack surface.

When session recording tools (e.g., Hotjar, FullStory, Microsoft Clarity) are deployed on portals where users interact with AI systems, the recordings may capture prompts, AI responses, sensitive data inputs, and system behaviour patterns. If the recording service is compromised, all captured session data is exfiltrated — including any AI interaction data.

This technique is particularly severe when:
- Cookie consent is absent or explicitly disabled in source code
- The portal serves government, defence, or critical infrastructure users
- AI system prompts or responses are visible in the recorded session
- The tracking service operates in a foreign jurisdiction

## Attack Vector

**Prerequisites:**
- Target portal has third-party tracking scripts embedded
- No or insufficient cookie consent mechanism
- Attacker has access to the third-party service account (via credential compromise, insider access, or service-level vulnerability)

**Procedure:**
1. Identify third-party tracking services embedded in target portal via page source analysis or browser DevTools Network tab
2. Determine whether cookie consent is present and functional (check source for consent management platform configuration, disabled flags like `isCookieBannerEnabled: false`)
3. Assess what data the tracking service captures (session recording vs. analytics vs. advertising)
4. If session recording is active: user interactions with AI systems are being recorded, including prompts, responses, and potentially sensitive data
5. Compromise the third-party service account to access recorded sessions — OR — exploit a vulnerability in the tracking service itself
6. Exfiltrate all recorded session data, including AI interaction patterns

## Detection

- Audit all third-party scripts loaded on AI-serving portals using browser DevTools → Network tab
- Search page source for tracking service identifiers (Hotjar site ID, Google Analytics measurement ID, LinkedIn Insight tag, Facebook Pixel)
- Check for cookie consent mechanism presence and functionality
- Review Content Security Policy for whitelisted third-party domains
- Monitor outbound data flows from portal pages to third-party endpoints
- Verify tracking services are documented in the organisation's data processing register

## Remediation

- **Audit all third-party scripts** on portals that serve or interact with AI systems
- **Implement functional cookie consent** with opt-in for non-essential services (not just a notice — a mechanism that blocks scripts until consent is given)
- **Remove session recording tools** from pages where users interact with AI systems (prompts, responses, configuration)
- **Review data processing agreements** with all embedded third-party services
- **Implement Content Security Policy** that restricts script sources to approved domains only
- **Conduct privacy impact assessment** for all third-party integrations on AI-serving portals
- **Ensure compliance** with applicable privacy legislation (Australian Privacy Act APP 5, GDPR Article 6/7, ePrivacy Directive)
