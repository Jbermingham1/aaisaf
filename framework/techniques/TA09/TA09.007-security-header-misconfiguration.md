# TA09.007 — Security Header Misconfiguration

## Overview

| Field | Value |
|-------|-------|
| **ID** | TA09.007 |
| **Tactic** | [AI-Enhanced Application Attacks](../../tactics/TA09-ai-application.md) |
| **Severity** | Medium-High |
| **AISS Score** | 6.5 |
| **System Types** | A, B, C, D, E, F, G |

## Description

Web portals serving AI systems lack standard security headers, increasing the attack surface for cross-site scripting (XSS), clickjacking, MIME sniffing, and data injection attacks. When AI systems generate dynamic content (responses, code, HTML), the absence of security headers means the browser has no policy to prevent malicious content from executing.

This is particularly severe for AI-serving portals because:
- AI-generated output may include executable content (JavaScript, HTML) that a Content Security Policy would block
- Clickjacking via missing X-Frame-Options allows attackers to overlay AI interfaces in deceptive frames
- Missing Referrer-Policy leaks AI interaction URLs (which may contain prompt data) to third parties
- Missing X-Content-Type-Options enables MIME confusion attacks on AI-generated downloads

**Standard security headers that should be present:**

| Header | Purpose |
|--------|---------|
| Content-Security-Policy (CSP) | Prevents XSS by restricting script sources |
| X-Frame-Options | Prevents clickjacking by restricting iframe embedding |
| X-Content-Type-Options | Prevents MIME sniffing attacks |
| Referrer-Policy | Controls information leakage via referrer headers |
| Strict-Transport-Security (HSTS) | Enforces HTTPS connections |
| Permissions-Policy | Restricts browser feature access (camera, microphone, geolocation) |

## Attack Vector

**Prerequisites:**
- Target portal serves AI system interface
- One or more standard security headers are missing or misconfigured

**Procedure:**
1. Send HTTP HEAD request to target portal (`curl -sI https://target.com`)
2. Analyse response headers against security header baseline
3. Identify missing headers and their specific attack implications
4. Exploit the gap — e.g., missing CSP enables injection of malicious scripts via AI output; missing X-Frame-Options enables clickjacking the AI interface

## Detection

- HTTP response header analysis via `curl -sI` or browser DevTools
- Automated scanning with SecurityHeaders.com, Mozilla Observatory, or equivalent
- CI/CD pipeline checks for security header presence on deployment
- Regular security header audits as part of posture assessment

## Remediation

- **Implement Content Security Policy** restricting script sources to trusted domains only — this is the highest-priority header for AI-serving portals
- **Add X-Frame-Options: DENY** or **SAMEORIGIN** to prevent clickjacking
- **Add X-Content-Type-Options: nosniff** to prevent MIME confusion
- **Implement Referrer-Policy: strict-origin-when-cross-origin** to limit URL leakage
- **Enable HSTS** with `max-age=31536000; includeSubDomains; preload`
- **Add Permissions-Policy** restricting unnecessary browser features
- **Test header configuration** across all environments (dev, staging, production)

These are server configuration changes, not application code changes — typically achievable within hours, not days.
