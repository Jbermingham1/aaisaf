# TA09.008 — Advertising Tracker Embedding on Government/Enterprise Portals

## Overview

| Field | Value |
|-------|-------|
| **ID** | TA09.008 |
| **Tactic** | [AI-Enhanced Application Attacks](../../tactics/TA09-ai-application.md) |
| **Severity** | High |
| **AISS Score** | 7.2 |
| **System Types** | A, B, C, D, E, F, G |

## Description

Government, critical infrastructure, or enterprise portals that serve or interact with AI systems have advertising network tracking (Google Ads/DoubleClick, Meta Pixel, LinkedIn Insight Tag) explicitly embedded or whitelisted in their Content Security Policy. This means users of these portals — including government officials, defence personnel, and regulated industry stakeholders — are being tracked by commercial advertising networks while interacting with AI systems.

The advertising tracking creates multiple risk vectors:
- **Data sovereignty risk:** User interaction data (including AI prompts and behavioural patterns) flows to foreign-owned advertising networks
- **Profiling risk:** Advertising networks build behavioural profiles of government/defence users based on their portal interactions
- **Supply chain risk:** If the advertising network is compromised, the tracking pixel becomes an exfiltration channel
- **Compliance risk:** Government portals tracking citizens for advertising purposes may violate public sector privacy obligations

This is particularly concerning when the portal's Content Security Policy explicitly whitelists advertising domains (e.g., `*.doubleclick.net`), indicating a deliberate configuration choice rather than an oversight.

## Attack Vector

**Prerequisites:**
- Target portal is government, defence, or critical infrastructure
- Advertising tracking scripts are embedded or whitelisted in CSP
- Portal serves AI system interactions

**Procedure:**
1. Analyse portal's Content Security Policy headers for whitelisted advertising domains (`doubleclick.net`, `facebook.net`, `ads.linkedin.com`, etc.)
2. Inspect page source for embedded advertising pixels or conversion tracking scripts
3. Map data flow: what user behaviour data is transmitted to the advertising network
4. Assess whether AI interaction data (prompts, responses, system configuration visible in UI) is captured by the tracking scripts
5. If advertising network account is compromised → attacker gains access to behavioural profiles of government/defence portal users

## Detection

- Content Security Policy header analysis — search for advertising network domains in `script-src`, `frame-src`, `connect-src` directives
- Page source inspection for advertising pixel scripts
- Network tab analysis — monitor outbound requests to advertising domains during portal usage
- DNS-level monitoring for connections to known advertising tracker domains
- Data flow mapping for all third-party integrations on government/enterprise portals

## Remediation

- **Remove advertising network domains** from Content Security Policy immediately
- **Remove all advertising tracking scripts** from government/enterprise portals
- **Implement strict CSP** allowing only first-party and approved analytics domains
- **Conduct data flow audit** to identify all third-party data recipients
- **Implement Subresource Integrity (SRI)** for all remaining third-party scripts
- **Establish third-party integration governance** — approval process for embedding any external service on government portals
- **Review procurement contracts** with web development vendors to prevent advertising tracker inclusion
